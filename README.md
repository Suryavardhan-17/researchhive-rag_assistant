# ResearchHive — Evidence-First Document Q&A

A runnable document retrieval application with **PDF ingestion, chunking, TF-IDF search, source/page citations, FastAPI and Streamlit**. Designed as a transparent baseline that works without paid APIs.

> **Scope disclosure:** This rebuild uses TF-IDF retrieval and extractive evidence display, **not** Llama 3.1, LangChain, embeddings, FAISS, or generative AI. Those are planned upgrades, not completed features. Do not represent it as an LLM-based RAG implementation yet.

## Architecture
`PDF → pypdf text extraction → overlapping chunks → TF-IDF index → cosine similarity → cited passages → Streamlit UI`

## Quick start (Python 3.11+)
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.api:app --reload
```
In another terminal:
```bash
streamlit run ui.py
```
Open `http://localhost:8501`; upload a text-based PDF and ask questions. API docs: `http://localhost:8000/docs`.

## Tests
```bash
pytest -q
```

## Limitations and next upgrades
- In-memory index resets on restart; add persistent vector store.
- Text-based PDFs only; add OCR for scans.
- Baseline retrieval uses lexical similarity; add embedding models and FAISS, then evaluate recall@k.
- Evidence is quoted from retrieved passages, not generated by an LLM.
- Demo has no user authentication; do not expose it publicly with private files.

## Responsible publication
Use only public or self-authored PDFs. Never commit secrets or private documents. Benchmark metrics must be measured on a documented test set before adding them to a resume.
